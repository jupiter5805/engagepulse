# Four-week plan before application deadline (6 Dec 2026)

## Phase 1 — Data and transparent baseline (days 1–5)
- Load OULAD, document tables and join keys.
- Build day-28 snapshot without post-cutoff information.
- Baseline Logistic Regression and leakage unit tests.
- Publish genuine metric results and documented limitations.

## Phase 2 — Scientific evaluation (days 6–12)
- Theory-aligned features, assessment timeliness and resource activity types.
- Model comparisons (Logistic Regression, Random Forest, gradient boosting).
- Forward-in-time and cross-module holdouts; confidence intervals, calibration.
- Error analysis, fairness evaluation; decision thresholds at tutor capacity.

## Phase 3 — Data/ML product (days 13–19)
- PostgreSQL features, FastAPI scoring endpoint, model registry/version.
- Streamlit or lightweight React dashboard: case-level explanation, trends, support queue.
- Audit trail and intervention *simulation* (not invented real-world impact).
- Docker, CI tests, data dictionary and monitoring plan.

## Phase 4 — KTP evidence (days 20–26)
- Research literature matrix and public competitor review.
- Stakeholder personas, interview guide, concise product/business case.
- Ethics/model card, installation instructions, reproducible demo.
- Three-minute walkthrough, CV bullet points and a technical presentation.

## Done criteria

A reviewer can reproduce the metrics from cited public data, see exactly what was available at prediction time, test on unseen cohorts, understand tradeoffs under limited tutoring capacity, and inspect the human support workflow. No unverifiable performance or retention uplift claims.
